= Get started with the docs.netapp.com MCP server
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Get started by connecting your AI development environment, such as Visual Studio Code with GitHub Copilot, Claude Desktop, or custom Python agents, to the docs.netapp.com Model Context Protocol (MCP) server. After configuration, learn when to use each docs.netapp.com MCP tool for optimal results. 

== Before you begin

Before configuring the docs.netapp.com MCP server, verify the following:

* You have reviewed the information in link:learn-mcp-server.html[Learn about the docs.netapp.com MCP server].
* Visual Studio Code is installed with the GitHub Copilot extension enabled.
* If you require external client access, you must have an active *NetApp APIM subscription key*. To request a key, contact the IE development team.
* You have network access to the docs.netapp.com MCP endpoint: `\https://docs-stage.netapp.com/mcp` (or production endpoint `\https://docs.netapp.com/mcp`).

== Step 1: Configure your development environment

Choose the setup option for your environment.

=== Visual Studio Code setup

You can connect to the MCP server from Visual Studio Code using GitHub Copilot by configuring an `mcp.json` file.

.Steps

. From your project workspace in Visual Studio Code, complete the following:

.. Create a folder named `.vscode`
.. Create a file within the folder called `mcp.json`

. Configure the `mcp.json` file depending on whether you want to configure remote, local or external access to the MCP server. 
+
[role="tabbed-block"]
====
.Remote MCP Server (Recommended)
--

[source,json]
----
{
  "servers": {
    "netapp-docs-mcp": {
      "type": "http",
      "url": "https://apimanagement-rg-devops.azure-api.net/netappdocs/mcp"
    }
  }
}
----

NOTE: Access to this endpoint is restricted. Ensure your device is connected to the NetApp corporate network (for example, via VPN) before attempting to connect.

--
.Local MCP server
--
You can access the MCP server locally.

[source,json]
----
{
  "servers": {
    "netapp-docs-mcp": {
      "type": "http",
      "url": "http://localhost:8000"
    }
  }
}
----

--
.External access (Non-VPN users)
--
If you are not connected to the NetApp corporate network (VPN), you can still access the MCP service using an API subscription key.  If you do not already have a key, contact the IE development team to request access.

[source,json]
----
{
  "servers": {
    "netapp-docs-mcp": {
      "type": "http",
      "url": "https://apimanagement-rg-devops.azure-api.net/netappdocs/mcp",
      "headers": {
        "Ocp-Apim-Subscription-Key": "${input:Ocp-Apim-Subscription-Key}"
      }
    }
  },
  "inputs": [
    {
      "type": "promptString",
      "id": "Ocp-Apim-Subscription-Key",
      "description": "Enter your access key",
      "password": true
    }
  ]
}
----

--
====

. Save the file. 

. Optionally, configure global access. 
+
To make the NetApp Docs MCP Server available across all Visual Studio Code projects and workspaces, add the configuration to your global user settings directory.
+
* *Windows*: `C:\Users\<your_username>\AppData\Roaming\Code\User\mcp.json`
* *macOS*: `~/Library/Application Support/Code/User/mcp.json`
+
Add the server definition:
+
[source,json]
----
{
  "servers": {
    "netapp-docs-mcp": {
      "type": "http",
      "url": "https://docs-stage.netapp.com/mcp"
    }
  }
}
----
+
IMPORTANT: Restart Visual Studio Code after modifying global `mcp.json` files for the configuration to take effect.

. Verify the configuration.
.. Open Visual Studio Code in your workspace.
.. Confirm that the `.vscode/mcp.json` file is present.
.. Ask a question using Copilot. 
+
.Example
+
_What are the differences between ONTAP and Cloud Volumes ONTAP?_

=== Python AI agent integration

For custom AI applications or Python agent pipelines, connect directly using an MCP client library:

[source,python]
----
from mcp import MCPClient

# Initialize connection to the NetApp Docs MCP Server
client = MCPClient("https://docs-stage.netapp.com/mcp")

# Call the RAG answer tool
response = client.call_tool("netapp_docs_ask", {
    "question": "What are the steps to perform a non-disruptive ONTAP upgrade?"
})

print(response)
----

=== Claude Desktop configuration

To register the docs.netapp.com MCP server with Claude Desktop, update your configuration file:

* *macOS*: `~/Library/Application Support/Claude/claude_desktop_config.json`
* *Windows*: `%APPDATA%\Claude\claude_desktop_config.json`

[source,json]
----
{
  "mcpServers": {
    "netapp-docs-mcp": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "https://docs-stage.netapp.com/mcp"
      ]
    }
  }
}
----


==  Step 2: Use the docs.netapp.com MCP server

After you've configured the MCP server, you can interact with NetApp technical documentation directly inside Visual Studio Code or your chosen client interface. The docs.netapp.com MCP server has three primary tools. Understanding when to use each ensures optimal performance.

* Start with `netapp_docs_ask` for most questions.
* Use `netapp_docs_search` for keyword-based discovery.
* Use `netapp_docs_fetch` to retrieve detailed document content.
* Use clear, complete questions instead of short or vague queries.
* Responses are always grounded in official NetApp documentation.

NOTE: MCP tools are independent, there is no required execution flow. However, it is recommended to start with `netapp_docs_ask` for most scenarios. This provides the fastest and most complete results.

=== Use `netapp_docs_ask` (recommended default)

Generates complete, synthesized answers grounded in official documentation with reference citations. Use this for how-to questions, troubleshooting, conceptual explanations, and comparison.

Example configuration and how-to questions::
* _How do I configure SnapMirror replication between two ONTAP clusters?_
* _How do I perform a non-disruptive ONTAP upgrade?_
* _What are the steps to set up SVM peering in ONTAP?_
* _How do I create and manage aggregates in ONTAP?_
* _How do I configure NFS access on an ONTAP cluster?_

Example troubleshooting questions::
* _SnapMirror replication is failing — how do I resolve connection errors?_
* _Why are my volumes not visible after a failover in ONTAP?_
* _What are common causes of high latency in ONTAP systems?_
* _Why are my REST API calls not returning expected ONTAP objects?_
* _How do I troubleshoot CIFS/SMB connection issues in ONTAP?_

Example conceptual questions::
* _What is WAFL and how does write allocation work in ONTAP?_
* _How does SnapMirror replication work internally?_
* _What is the difference between an SVM and a cluster in ONTAP?_

Example comparison questions:: 

* _What is the key difference between SnapMirror and SnapVault?_
* _AFF vs FAS — which one should I use and when?_

=== Use `netapp_docs_search`
Discovers relevant documentation articles based on keyword queries. Use this during early research or topic discovery.

NOTE:  Use short keyword-style queries with `netapp_docs_search`. For complete answers, switch to `netapp_docs_ask`.

Example keyword-style queries for product or feature discovery::
* _ONTAP upgrade_
* _SnapMirror configuration_
* _SVM peering_
* _ONTAP REST API_
* _NetApp Console setup_

Example keyword-style queries for documentation lookup::

* _ONTAP installation guide_
* _SnapMirror best practices_
* _CIFS configuration ONTAP_
* _NFS setup ONTAP_
* _ONTAP networking configuration_

Example keyword-style queries for troubleshooting topics (discovery stage)::

* _SnapMirror failure_
* _ONTAP latency issues_
* _CIFS connection problems_
* _Volume not visible ONTAP_
*_ONTAP API errors_


Example keyword-style queries for concepts and features::

* _WAFL architecture_
* _ONTAP storage efficiency_
*_SnapVault overview_
* _MetroCluster concepts_

=== Use `netapp_docs_fetch`
Retrieves full, structured content for a specific article URL returned by search. Use when step-by-step procedures or exhaustive technical details are required.

NOTE: `netapp_docs_fetch` is typically used after `netapp_docs_search` when you want to inspect a specific document.
