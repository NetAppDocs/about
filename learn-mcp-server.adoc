= Learn about the docs.netapp.com MCP server
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
The docs.netapp.com MCP server provides a standardized, agent-ready integration layer in front of existing NetApp documentation and Retrieval-Augmented Generation (RAG) services. It allows AI agents, such as GitHub Copilot in Visual Studio Code, Claude Desktop, and custom Python AI agents, to interact with enterprise technical knowledge using natural language without requiring direct REST API integration or custom pipeline development.

By providing structured access to NetApp documentation, the docs.netapp.com MCP server enables AI agents to:

* Discover relevant documentation
* Retrieve complete document content
* Generate answers based on documentation (RAG based answer generation)
* Produce grounded, verifiable responses

== Use cases

You can use the docs.netapp.com MCP server to:

* Enhance agentic development environments such as Visual Studio Code, GitHub Copilot, Claude Desktop, and custom agents with NetApp content.
* Support engineering and support workflows that need trusted documentation during active work.
* Reduce the need to build and maintain custom search, retrieval, or RAG integrations.
* Provide answers that are grounded in official NetApp documentation and easy to verify.

== How the docs.netapp.com MCP server works

The MCP server acts as an interface to official NetApp documentation and returns grounded answers from published content.

* The AI agent sends a request to the MCP server.
* The MCP server retrieves relevant documentation.
* The system returns a structured, grounded response.

This simple exchange helps AI agents stay aligned with authoritative documentation while keeping the interaction model predictable.

== Requirements

* Access is managed through NetApp API Management (APIM). Internal requests are authenticated through network IP filtering, and external or partner requests use an APIM subscription key.
* Supported clients include MCP-compliant environments such as Visual Studio Code with GitHub Copilot, Claude Desktop, and Python-based agent frameworks.
* Users must follow the applicable NetApp documentation terms of use and access governance policies.

== Limitations

* The MCP server queries publicly published NetApp technical documentation. It does not access private tenant data or internal user profile information.
* Content is limited to published documentation and does not replace product telemetry, cluster state, or other environment-specific data sources.
* Response quality depends on how the client agent uses the available tools and follows up on search results.
* The service is deployed statelessly on scalable cloud infrastructure, so latency and freshness depend on the downstream documentation and RAG services.
