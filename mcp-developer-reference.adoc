== MCP endpoint

The docs.netapp.com MCP server has a remote HTTP endpoint that exposes NetApp documentation through a standard MCP interface. Client applications such as GitHub Copilot in Visual Studio Code, Claude Desktop, and custom Python agent frameworks can connect to it through a supported MCP client.

Use the following endpoint when connecting remotely to the server:

[source,json]
----
{
  "servers": {
    "netapp-docs-mcp": {
      "type": "http",
      "url": "https://docs-stage.netapp.com/mcp"
    }
  }
}
----


== Tools

The docs.netapp.com MCP server exposes a small, focused tool set for documentation discovery and retrieval. 

The server currently provides the following tools:

* `netapp_docs_ask`: Generates documentation-grounded answers using a retrieval-augmented generation workflow.
* `netapp_docs_search`: Discovers relevant NetApp documentation pages using keyword and natural-language queries.
* `netapp_docs_fetch`: Retrieves the structured content of a specific documentation page or article.
* `health_check`: Validates MCP server availability.

=== netapp_docs_ask (recommended default)

Generates complete, synthesized answers using RAG that are grounded in official documentation with reference citations. 

[cols="2,2" options="header"]
|===
// header row
| Uses
| Input/Output

// first body row
a|

* How-to questions
* Conceptual explanations
* Troubleshooting
* Comparisons
a|

*Input:* A question

*Output:* A synthesized answer with references

// table end
|===


Example configuration and how-to questions::
* _How do I configure SnapMirror replication between two ONTAP clusters?_
* _How do I perform a non-disruptive ONTAP upgrade?_
* _What are the steps to set up SVM peering in ONTAP?_
* _How do I create and manage aggregates in ONTAP?_
* _How do I configure NFS access on an ONTAP cluster?_

Example troubleshooting questions::
* _SnapMirror replication is failing — how do I resolve connection errors?_
* _Why are my volumes not visible after a failover in ONTAP?_
* _What are common causes of high latency in ONTAP systems?_
* _Why are my REST API calls not returning expected ONTAP objects?_
* _How do I troubleshoot CIFS/SMB connection issues in ONTAP?_

Example conceptual questions::
* _What is WAFL and how does write allocation work in ONTAP?_
* _How does SnapMirror replication work internally?_
* _What is the difference between an SVM and a cluster in ONTAP?_

Example comparison questions:: 

* _What is the key difference between SnapMirror and SnapVault?_
* _AFF vs FAS — which one should I use and when?_

=== netapp_docs_search
Discovers relevant documentation using keyword and natural language queries. Use this during early research or topic discovery.

[cols="2,2" options="header"]
|===
// header row
| Uses
| Input/Output

// first body row
a|

* Keyword-based queries
* Explore available content
* Find relevant documentation pages
* Example queries (keyword style)
* Product or feature discovery
a|

*Input:* A natural language query

*Output:* A list of documents with title, summary, and URL

// table end
|===

NOTE:  Use short keyword-style queries with `netapp_docs_search`. For complete answers, switch to `netapp_docs_ask`.

Example keyword-style queries for product or feature discovery::
* _ONTAP upgrade_
* _SnapMirror configuration_
* _SVM peering_
* _ONTAP REST API_
* _NetApp Console setup_

Example keyword-style queries for documentation lookup::

* _ONTAP installation guide_
* _SnapMirror best practices_
* _CIFS configuration ONTAP_
* _NFS setup ONTAP_
* _ONTAP networking configuration_

Example keyword-style queries for troubleshooting topics (discovery stage)::

* _SnapMirror failure_
* _ONTAP latency issues_
* _CIFS connection problems_
* _Volume not visible ONTAP_
* _ONTAP API errors_


Example keyword-style queries for concepts and features::

* _WAFL architecture_
* _ONTAP storage efficiency_
* _SnapVault overview_
* _MetroCluster concepts_

=== netapp_docs_fetch
Retrieves full, structured content for a specific article URL returned by search. Use when step-by-step procedures or exhaustive technical details are required.

[cols="2,2" options="header"]
|===
// header row
| Uses
| Input/Output

// first body row
a|

* Extract step-by-step procedures
* Read full documentation
* Retrieve deep technical details
a|

*Input:* A document URL

*Output:* Structured text content (title, summary, and article)
// table end
|===



NOTE: `netapp_docs_fetch` is typically used after `netapp_docs_search` when you want to inspect a specific document. Use this tool when you have already identified the document and need detailed content.
